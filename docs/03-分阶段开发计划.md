# 商机管理系统 · 分阶段开发计划

> 依据：PRD 第 17 节版本规划 + 第 6 节模块优先级。
> 前置：以高保真原型（Vue3+Element Plus）为前端基座重构，后端按《02-系统架构设计》落地 Spring Boot 多租户分层。
> 节奏假设：以 2 周为一个 Sprint。下方周期为工程量估算，可按实际团队规模缩放。

---

## 0. 总览：版本 → 模块映射

| 版本 | 主题 | 覆盖模块 | 预估周期 |
|------|------|----------|----------|
| **阶段 0** | 工程基座 + 设计系统落地 | 前端重构骨架、后端脚手架、CI、租户中间件 | 2–3 周 |
| **V1.0 MVP** | 多租户 + 商机/客户主流程闭环 | M01–M10、M12、M16、M18、M19(核心) | 8–10 周 |
| **V1.1 增强** | 交易履约 + 营销 + 公海 + 报表 | M05-07、M11、M13、M14、M15、M17(基础) | 6–8 周 |
| **V1.2 自动化** | 规则引擎 + 配置化 + 审批 | M06-04、M07-04、阶段规则、通知规则、字段配置、导出审批 | 4–6 周 |
| **V2.0 智能化** | 预测 + 画像 + 集成 + 移动端 | M17(预测)、M20、商机评分、客户画像、移动端 | 8–12 周 |

## 阶段 0：工程基座（2–3 周，强制前置）

**目标**：可运行的前后端骨架 + 设计系统固化 + 多租户底座，后续模块在此之上平行开发。

### 前端（基座重构）

| 任务 | 产出 | 验收 |
|------|------|------|
| 抽取设计 token | `styles/tokens.css` + `base.css`（来自高保真 styles.css） | Element Plus 主色对齐 `#2563eb` |
| 搭建布局骨架 | `layouts/DefaultLayout.vue`（sidebar+topbar+page-body） | 与高保真截图像素一致 |
| 引入 Router + Pinia | 路由表对应 menu 四分组 + 登录守卫 + 菜单权限 meta | 路由跳转替代 `currentPage` ref |
| API 层 + Mock | `services/` + 请求拦截器（token/租户头） + Mock adapter | 可切换 Mock/真实 |
| 权限指令 | `directives/perm.ts`（`v-perm`） | 按钮按权限码显隐 |
| 通用组件迁移 | PageHeader / KpiCardGrid / OpportunityTable / MiniTable / RecordGrid / ActivityTimeline / ContactCardList / GenericTablePage | 与高保真一致，TS 化 |
| 去运行时编译 | SFC `<template>` 改写，移除 `vue.esm-bundler` alias | `vue-tsc` 通过 |

### 后端（脚手架）

| 任务 | 产出 |
|------|------|
| 工程分层 | Spring Boot 3 多模块（gateway/common/biz 域） |
| 租户中间件 | token 解析 → ThreadLocal → MyBatis-Plus 租户拦截器 |
| 鉴权基座 | JWT + RBAC 骨架 + 统一异常/响应包装 |
| 审计切面 | `@AuditLog` AOP + audit_log 表 |
| 基础设施 | MySQL 8 + Redis + 对象存储(MinIO) + Flyway 迁移 |
| CI | 构建 + 单测 + 镜像 |

**里程碑 M0**：登录页 → 工作台空壳跑通，租户上下文贯穿一次完整请求，审计日志能落库。

## V1.0 MVP（8–10 周）

**目标**：单租户内商机/客户主流程完整闭环 + 多租户隔离 + 权限基线。这是 PRD「全流程闭环」验收的核心。

### Sprint 1（2 周）— 平台底座 P0

- **M01 登录与账号**：租户识别（编码/域名/手机邮箱）、登录、改密、失败锁定、登录审计。
- **M02 租户管理**：平台超管后台开通租户、状态（试用/正常/冻结/停用）、租户级配置入口。
- **M03 组织与用户**：部门树（多级、拖拽排序）、用户 CRUD、上下级关系、角色分配。
- **M04 角色权限（RBAC+数据范围）**：角色配置菜单/操作权限、数据范围（本人/部门/部门及下级/全租户）。字段权限、阶段权限**后置到 V1.2**（按 PRD 18 风险建议）。

**里程碑 M1**：两个租户 A/B 创建完成，A 用户登录后菜单/数据按角色受限，跨租户访问被拒并审计。

### Sprint 2–3（4 周）— 商机与客户主体

- **M10 客户管理**：客户列表（筛选/去重/导入导出）、客户资料、联系人、下级客户树、客户归属与历史。
- **M05 商机列表**：7 视图（全部/我的/下属/我协作/下属协作/成交/公海占位）、筛选/排序/分页/列配置/保存视图。
- **M06 商机新增/编辑/导入**：单条新增（分区表单）、编辑（前后值留痕）、批量导入（模板/校验/预览/失败清单/异步进度）、商机转移、重复校验占位。
- **M16 附件中心**：上传/预览/下载/权限校验/签名 URL（版本与水印基础）。

**里程碑 M2**：客户与商机可创建、可导入、可在列表多视图查看，附件可传可下且租户隔离。

### Sprint 4–5（4 周）— 跟进、协作、详情、闭环

- **M07 商机跟进**：跟进记录时间线、下次跟进提醒（待办/逾期）、阶段推进（必填校验）、输单/作废占位。
- **M08 商机详情**：阶段条 + 多 Tab（概况/联系人/跟进/任务/订单占位/报价占位/费用占位/附件/操作日志）+ 关键指标侧栏。
- **M09 协作管理**：添加协作人（用户/部门/角色）、协作权限模板、协作任务、取消协作。
- **M12 任务中心**：任务关联商机/客户、状态流、提醒、看板。
- **M19（核心）系统配置**：商机阶段配置（名称/顺序/赢率/必填）、编号规则。

**里程碑 M3（V1.0 验收）**：新增→跟进→协作→任务→（报价/订单占位）→成交→附件→日志全流程闭环；M18 审计覆盖关键操作；多租户隔离与多用户权限验收通过。

## V1.1 增强（6–8 周）

**目标**：补齐交易履约、营销触达、公海运营与基础经营分析。

| Sprint | 模块 | 重点 |
|--------|------|------|
| S6（2周） | **M13 报价/产品** + **M14 订单/发票/退款** | 产品库、报价单多版本/折扣/税率/PDF 导出、订单关联回写成交金额、发票/退款记录 |
| S7（2周） | **M15 费用管理** + **M05-07 公海池** | 费用录入/统计、商机&客户公海领取/分配/回收/防撞 |
| S8（2周） | **M11 短信中心** | 模板/签名/变量、发送/定时、黑名单退订、余额与频控 |
| S9（2周） | **M17（基础）报表分析** | 销售漏斗、跟进质量、成交分析（按部门/人员/时间筛选 + 图表 + 明细导出） |

**里程碑 M4**：商机成交后可生成订单与财务记录；短信发送前校验余额/模板/黑名单并记录；漏斗/跟进质量/成交分析口径正确。

## V1.2 自动化（4–6 周）

**目标**：把硬编码规则升级为租户可配置 + 引入审批与高级权限。

- **M19 完整配置化**：自定义字段（文本/数字/日期/枚举/人员/附件）贯穿表单/列表/筛选/导入；消息通知规则配置。
- **阶段规则引擎（M07/10.1）**：阶段必填校验、回退权限、成交/输单必填项。
- **审批**：报价审批（M13-03）、费用审批（M15-02）、导出审批（M04-04）。
- **M06-04 重复校验**：按租户配置查重规则（名称/手机/信用代码/组合）+ 合并提示。
- **字段权限 + 阶段权限**（PRD 18 风险中分阶段上线的部分）：手机号/财务/毛利脱敏，阶段动作权限。

**里程碑 M5**：管理员无需开发即可调整字段、阶段、通知与审批规则；敏感字段按角色脱敏不可绕过。

## V2.0 智能化（8–12 周）

- **M17 预测分析**：基于预计成交时间/金额/阶段赢率的销售额预测 + 风险列表。
- **商机评分 / 客户画像**：评分模型、客户 360 画像。
- **M20 开放接口**：数据 API（租户鉴权+限流）、Webhook（商机创建/阶段变更/成交/客户变更）、SSO 对接。
- **移动端**：核心商机/客户/跟进/审批的移动适配。
- **智能提醒**：基于规则/模型的跟进提醒与风险预警。

## 风险与依赖

| 风险（PRD 18） | 缓解 | 影响阶段 |
|----------------|------|----------|
| 租户隔离不严 | 服务层/SQL/缓存/文件统一租户上下文 + 自动化越权测试 | 阶段 0 必须先解决 |
| 权限模型过复杂 | 先 RBAC+数据范围，字段/阶段权限延后到 V1.2 | V1.0 / V1.2 |
| 导入数据质量差 | 模板校验 + 预览确认 + 失败清单 + 重复检测 + 回滚 | V1.0 (M06) |
| 短信合规 | 模板审核 + 退订 + 黑名单 + 频控 + 敏感词 | V1.1 (M11) |
| 报表口径争议 | 开发前定义成交金额/转化率/及时率口径 | V1.1 (M17) |
| 归属冲突 | 明确客户归属/负责人/协作/公海优先级 | V1.0 (M10) / V1.1 (公海) |

**业务确认依赖（PRD 18.1）**：已于 2026-06-03 **全部定版**（D1–D8，见《05-关键设计决策记录》），无悬置项。阶段定义、客户唯一性、公海、报价审批、短信、计费的规则与默认阈值均已确定并做成可配置，研发无需再等口径。

## 跨阶段质量门禁

每个里程碑合并前必须满足：

1. **多租户隔离回归**：A/B 双租户越权用例全绿（列表/详情/导出/附件 URL/接口）。
2. **权限回归**：销售/主管/管理员三角色数据范围用例通过。
3. **审计完整性**：新增模块的关键操作均落审计日志（含前后值）。
4. **性能**：核心列表/详情 P95 ≤ 2s（造数到 PRD 16 规模做压测）。
5. **视觉一致**：前端页面与高保真原型截图比对无明显回退。
6. **类型与构建**：`vue-tsc` + 后端编译 + 单测在 CI 通过。
