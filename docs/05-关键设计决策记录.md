## D1 · 商机阶段定义与回退规则 ✅ V1.0

**阶段链采用高保真原型那套**（与 UI、权限码、测试、初始化数据一致）：

| 阶段 | code | 默认赢率 | 配色 | 类型 |
|------|------|----------|------|------|
| 初步接触 | `prospecting` | 10% | gray | 进行中 |
| 需求确认 | `qualifying` | 30% | cyan | 进行中 |
| 方案报价 | `proposal` | 50% | blue | 进行中 |
| 商务谈判 | `negotiation` | 70% | orange | 进行中 |
| 赢单 | `won` | 100% | green | 终态-赢 |
| 输单 | `lost` | 0% | red | 终态-输 |
| 作废 | `void` | 0% | gray | 终态-废 |

- **回退**：允许，但**仅销售主管（SALES_MANAGER）与租户管理员（TENANT_ADMIN）**，销售人员不可回退；每次回退写审计。→ `opp:stage:rollback` 仅授予这两角色。
- **成交必填**：成交金额、成交时间、成交说明。**V1.0 不强制关联订单**（订单为 V1.1 能力）。
- **输单必填**：输单原因、竞品信息、复盘说明。
- **落点**：`opportunity_stage` 种子（09/10）、`required_fields` JSON 承载必填校验。

## D2 · 客户唯一性规则 ✅ V1.0

| 字段 | 规则 | 处理 |
|------|------|------|
| 统一社会信用代码 | 租户内唯一 | 填写后强校验，重复禁止保存 |
| 客户名称 | 不唯一 | "疑似重复客户"软提示，允许继续保存 |
| 联系人手机号 | 不唯一 | 可在多客户下重复 |
| 名称+区域+行业 | V1.2 智能查重 | V1.0 不拦截 |

- **统一社会信用代码 V1.0 不设必填**（早期线索常拿不到完整工商信息）。
- **工程约束**：信用代码空字符串必须转 `NULL` 入库，否则 `UNIQUE(tenant_id, credit_code)` 会把多个空串误判重复。
- **落点**：`customer` 表 `uk_customer_credit`（09，允许多 NULL）。

## D3 · 协作人员是否独立成角色 ✅ V1.0

**不独立成角色**。删除 `COLLABORATOR`，售前/交付/法务等用本身角色（多为 `SALES`），被加为协作人后按 `opportunity_collaborator.permission_json` 获得**该商机对象级**操作权。

判定语义（交集，与《04》4.6 一致）：协作扩展"数据可见性 + 在对象上收窄动作"，**不赋予新动作类型**：
```
用户对商机 X 可执行动作 A ⟺ 角色拥有 A 的权限码
                          且 ( X 在数据范围内 或 (是 X 协作人 且 permission_json 允许 A) )
```

## D4 · 审计员数据范围 ✅ V1.0

审计员（`AUDITOR`）= **全租户只读**：`data_scope=TENANT`，仅授 `audit:view`/`audit:export` 及 `opp:view`/`customer:view`（只读），所有写操作码不授予。

## D5 · 公海回收/领取规则 ✅ V1.1（V1.0 预留字段）

| 项 | 规则 |
|----|------|
| 回收对象 | 客户、商机均支持入公海 |
| 自动回收 | 30 天无**有效跟进** |
| 有效跟进定义 | 电话/拜访/会议/微信或邮件沟通/方案沟通等被记录为跟进 |
| 领取权限 | 本租户销售人员、销售主管 |
| 个人领取上限 | 默认 50（可按租户配置） |
| 领取后归属 | 领取人成为负责人 |
| 保护期 | 领取后 7 天，保护期内不自动回收 |
| 通知 | 原负责人、领取人、直属主管 |
| 审计 | 回收、领取、释放均写审计 |

- **V1.0**：DDL 预留 `is_pool`、`pool_recycled_at`、`pool_reason`（09 已补），不做页面与接口主流程。
- **V1.1**：公海列表、领取/分配/回收/释放、上限、保护期、回收定时任务。

## D6 · 报价审批规则 ✅ V1.1

金额 + 折扣双阈值：

| 条件 | 审批 |
|------|------|
| 金额 < 100 万 且 折扣 ≥ 8 折 | 不审批 |
| 金额 ≥ 100 万 | 一级审批 |
| 折扣 < 8 折 | 一级审批 |
| 金额 ≥ 500 万 | 二级审批 |
| 折扣 < 7 折 | 二级审批 |
| 销售主动提交 | 支持 |

审批链：一级=直属主管；二级=直属主管 → 销售总监 / 租户管理员指定审批人。
**V1.0** 商机详情仅保留报价 Tab 占位；**V1.1** 做报价单、版本、PDF、审批流。

## D7 · 短信服务商与合规 ✅ V1.1

| 项 | 决策 |
|----|------|
| 默认服务商 | 阿里云短信 |
| 备用 | 腾讯云短信 |
| 技术 | `SmsProvider` 适配层，服务商可配 |
| 签名 | 每租户独立签名 |
| 模板 | 审核后启用 |
| 变量 | 客户姓名、商机名称、负责人、时间等 |
| 黑名单/退订 | 必须支持 |
| 频控 | 同手机号每日 ≤ 3 条；同租户每分钟限流 |
| 计费 | 按条扣减租户短信余额 |
| 审计 | 发送/失败/退订/黑名单命中均留日志 |

**V1.0** 不实现真实发送（最多页面占位/Mock）；**V1.1** 接入服务商。
