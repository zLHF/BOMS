# 商机管理系统 · 系统架构设计

> 依据：《商机管理系统 PRD 多用户多租户版 V1.0》。
> 技术栈：遵循 PRD 第 14 节建议 —— 前端 Vue3 + TS + Element Plus，后端 Spring Boot + MyBatis-Plus，MySQL 8 + Redis + 对象存储 + 消息队列。
> 定位：面向 B2B 销售团队的多租户商机与客户经营平台，支持商机全生命周期 + 客户 360 视图 + 团队协同 + 权限隔离 + 经营分析。

| 层级 | 选型 | 说明 |
|------|------|------|

| 鉴权 | JWT/Session + RBAC + ABAC | 见第 4 节 |

## 2. 多租户架构（PRD 4）

### 2.1 隔离模型：共享库 + `tenant_id` 逻辑隔离

- 所有业务表强制带 `tenant_id`，**服务层统一注入租户上下文**，禁止前端传入 `tenant_id` 作为可信条件。
- MyBatis-Plus 用 `TenantLineInnerInterceptor` 自动给 SQL 追加 `tenant_id` 条件，杜绝漏写。
- 平台级表（tenant、package、平台审计）不带 `tenant_id`，由平台超管访问。

### 2.2 五重隔离落地

| 隔离面 | 实现 |
|--------|------|
| 逻辑隔离 | MyBatis-Plus 租户拦截器 + `ThreadLocal` 租户上下文，请求入口解析、出口清理 |
| 权限隔离 | 默认拒绝跨租户；用户 token 绑定 `tenant_id`，越权访问返回 403 并审计 |
| 文件隔离 | 对象存储按 `tenant_{id}/` 前缀；下载生成限时签名 URL，校验租户+数据权限 |
| 缓存隔离 | Redis Key 模板 `{tenant_id}:{biz}:{key}`，统一封装 KeyBuilder |
| 审计隔离 | 审计日志记录租户、操作者、IP、设备、对象、动作、结果、前后值 |

### 2.3 租户生命周期（PRD 10 / M02）

`试用 → 正常 → 到期提醒 → 冻结 → 停用`。冻结后普通用户禁止登录，管理员仅见续费页。容量维度：用户数 / 商机数 / 客户数 / 短信条数 / 附件空间 / API 调用量，超限拦截新增并提示升级。

## 4. 权限模型（PRD 4.4 / M04）

**RBAC（角色）为主 + ABAC（数据范围/属性）为辅**，分阶段落地（先 RBAC+数据范围，字段/阶段权限后置，见风险 PRD 18）。

### 4.1 六类权限

| 类型 | 控制对象 | 前端落点 |
|------|----------|----------|
| 菜单权限 | 可见模块（商机/客户/报表/设置） | 路由 meta + 动态菜单生成 |
| 操作权限 | 按钮动作（增删改、导入导出、转移、移公海、发短信、审批） | `v-perm` 指令 |
| 数据权限 | 可访问的客户/商机/订单/费用/附件 | 后端数据范围过滤（前端不可信） |
| 字段权限 **（V1.2）** | 字段可见/可编辑/脱敏（手机号、财务、毛利） | 字段级渲染策略 |
| 阶段权限 | 阶段推进/回退/成交/输单/作废 | 阶段按钮显隐 + 后端校验 |
| 导出权限 | 导出字段/数量/水印/审批（审批 V1.2） | 导出入口控制 + 后端限制 |

> **字段权限为总体架构能力，V1.0 仅预留字段级渲染与接口扩展点；实际字段脱敏/明文授权在 V1.2 实现**（与《04-权限码表-V1.0》一致，`field:*:unmask` 码 V1.0 不开发）。

### 4.2 数据范围（PRD M04-02）

`本人 / 本部门 / 本部门及下级 / 指定部门 / 全租户 / 自定义规则`。基于组织树（部门 `parent_id`）+ 上下级关系（直属上级、部门负责人、矩阵负责人）计算可见数据集合，支撑「下属商机 / 下属协作」视图。

### 4.3 安全要点（PRD 13）

防越权、防 SQL 注入、XSS、CSRF、接口签名；字段脱敏不可被接口绕过（后端二次校验）；导出留痕 + 水印。

## 5. 数据模型（PRD 9）

### 5.1 核心实体与关系

```
tenant 1───* department 1───* user
tenant 1───* role          user *───* role
tenant 1───* customer 1───* contact
              customer 1───* customer(下级，parent_id 自关联)
              customer 1───* opportunity
opportunity *───1 customer
opportunity 1───* opportunity_follow
opportunity 1───* opportunity_collaborator *───1 user
opportunity 1───* quote 1───* quote_item *───1 product
opportunity 1───* order        order *───1 customer
task *───1 (object_type, object_id)   # 多态关联 客户/商机/订单
expense *───1 (object_type, object_id)
attachment *───1 (object_type, object_id)
audit_log *───1 (object_type, object_id)
```

### 5.2 关键表字段（摘录 PRD 9）

| 实体 | 表 | 关键字段 |
|------|------|----------|
| 租户 | `tenant` | id, name, code, domain, status, package_id, expire_at, config_json |
| 用户 | `user` | id, tenant_id, username, mobile, email, password_hash, status, dept_id |
| 部门 | `department` | id, tenant_id, parent_id, name, leader_id, sort |
| 角色 | `role` | id, tenant_id, name, data_scope, status |
| 权限 | `permission` | id, code, type, name |
| 客户 | `customer` | id, tenant_id, name, type, industry, region, owner_id, dept_id, level, status |
| 联系人 | `contact` | id, tenant_id, customer_id, name, role, mobile, email, is_key_person |
| 商机 | `opportunity` | id, tenant_id, title, customer_id, stage_id, source, amount, win_rate, owner_id, status, expected_close_at |
| 商机跟进 | `opportunity_follow` | id, tenant_id, opportunity_id, follow_type, content, result, next_time, creator_id |
| 商机协作 | `opportunity_collaborator` | id, tenant_id, opportunity_id, user_id, permission_json, status |
| 任务 | `task` | id, tenant_id, object_type, object_id, title, assignee_id, due_at, status, priority |
| 报价 | `quote` | id, tenant_id, opportunity_id, version, total_amount, status, valid_until |

| 审计日志 | `audit_log` | id, tenant_id, user_id, object_type, object_id, action, before_json, after_json, ip, created_at |

### 5.3 公共字段约束（PRD 9.1）

所有业务实体必须包含：`tenant_id, created_by, created_at, updated_by, updated_at, deleted`（逻辑删除）。

### 5.4 索引建议

- 高频列表：`(tenant_id, owner_id, stage_id, updated_at)`、`(tenant_id, customer_id)`。
- 多态关联：`(tenant_id, object_type, object_id)`（task/expense/attachment/audit_log）。
- 查重：客户 `(tenant_id, name)`、联系人 `(tenant_id, mobile)`。
- 性能目标（PRD 13 / 16）：10 万商机 + 50 万跟进下列表/详情 P95 ≤ 2s。

## 6. 状态机（PRD 10）

| 对象 | 状态流转 |
|------|----------|
| 商机阶段 | 初步接触 → 深入沟通 → 产品报价 → 成交确认 → 已成交（可配置输单/作废） |
| 任务 | 待处理 → 进行中 → 已完成（可进入 已逾期 / 已取消） |
| 协作 | 已邀请 → 进行中 → 已完成 / 已取消 |
| 订单 | 草稿 → 已确认 → 履约中 → 已完成（可取消） |
| 费用 | 草稿 → 审批中 → 已通过 / 已驳回 → 已报销 |
| 租户 | 试用 → 正常 → 到期提醒 → 冻结 → 停用 |

**阶段推进规则（PRD 10.1）**：可配置进入某阶段的必填项（如进「产品报价」需已有联系人和报价）；成交必填成交金额/时间/订单；输单必填原因/竞品/复盘；阶段回退仅主管或特定权限可操作且留痕。

| 能力 | 实现要点 |
|------|----------|
| 租户上下文 | 拦截器解析 token → `ThreadLocal` → MyBatis 拦截器消费 → 请求结束清理 |

## 8. 前端工程架构（基座重构）

```
src/
├─ main.ts                  # Element Plus + 图标 + Pinia + Router 装配
├─ App.vue                  # 仅渲染 <RouterView>
├─ layouts/
│   └─ DefaultLayout.vue    # sidebar + topbar + page-body 骨架
├─ router/
│   ├─ index.ts             # 路由表（对应 menu 分组）
│   └─ guard.ts             # 登录态 + 菜单权限守卫
├─ stores/                  # Pinia：auth/tenant/permission/dict
├─ services/                # API 层（先 Mock，后真实接口），含请求拦截/租户头
├─ directives/perm.ts       # v-perm 操作权限指令
├─ styles/                  # tokens.css + base.css（来自高保真 styles.css）
├─ components/              # PageHeader/KpiCardGrid/OpportunityTable/MiniTable...
├─ views/                   # 按模块：opportunity/customer/settings/...
└─ types/                   # TS 类型（实体、DTO、权限码）
```

要点：路由 meta 携带权限码与菜单分组；请求拦截器注入 `Authorization` 与租户标识（由后端从 token 解析为准，前端不可信传 tenant_id）；按钮权限在组件层统一处理（`v-perm`）。字段脱敏在 V1.0 仅预留组件层渲染扩展点，实际授权 V1.2 落地。详见《01-设计系统规范》第 5 节迁移要点。

## 9. 验收基线（PRD 16，关键项）

- **多租户隔离**：租户 A 用户无法通过列表/详情/导出/附件 URL/接口访问租户 B 任何数据。
- **多用户权限**：销售仅本人数据；主管见下属数据；管理员配权后实时（或重登）生效。
- **商机全流程（V1.0）**：新增→跟进→协作→任务→成交/输单→附件→日志闭环；**报价、订单、发票、退款为占位 Tab，不进入 V1.0 验收闭环**。V1.1 补齐报价→订单→发票/退款→费用闭环（与《03-分阶段开发计划》一致）。
- **批量导入**：含正确/错误数据的模板能校验并返回错误明细，不产生脏数据。
- **审计**：关键操作生成不可篡改记录（操作人/时间/IP/对象/前后值）。
- **性能**：10 万商机/50 万跟进下核心列表与详情满足 P95 ≤ 2s。
